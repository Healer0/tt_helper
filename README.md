# tt_fish · 钓鱼助手

面向 Windows PC版微信小游戏的 Python 图像识别钓鱼工具。通过屏幕截图判断阶段，以鼠标点击完成下钩、拉钩、黄条判定和结算返回，不读取游戏内存。当前仅支持微信小游戏。

[GitHub 项目](https://github.com/zz11-m/tt_fish) · [作者的哔哩哔哩主页](https://space.bilibili.com/488950689) · [更新记录](CHANGELOG.md)

> 本项目免费提供，用于学习与交流。无需购买授权、激活码或收费解锁；请从上面的项目地址获取源码。

当前版本 **1.6.0**，配置版本 **10**。新配置默认勾选“仅观察”和“不停钓”，每6个基准帧截图一次（约10次/秒），用连续往返运动计时预约黄条点击。预览默认隐藏，不自动保存轨迹、截图、运行日志或诊断ZIP。源码包包含完整源码和必要资源；Windows便携包另附运行环境。
## 功能

- 自动识别准备下钩、等待上钩、拉钩、黄条判定和结果展示。
- 支持跳过黄条或连续多轮黄条判定。
- 支持普通“开心收下”及蓝色、紫色、金黄色及红橙渐变纪录结算页，包括“刷新团队纪录”画面。
- 结果页等待后持续重试点击，避免首次点击没有被接受而停住。
- 点击默认随机偏移1.5%，可调至0～5%；限制在框选内并避免连续相同落点。
- 不停钓、次数／时长限制、截图间隔和快捷键可配置。
- 失焦暂停、手动紧急暂停、截图、手动录制和离线回放。

## 下载与启动

便携版解压后双击“启动钓鱼助手.bat”，无需另装Python。便携版`app/`仅含运行必需的`.pyc`字节码和图片，完整源码及开发文件另附于`source/tt_fish-版本号-source.zip`；查看详细README或修改源码时解压该归档。字节码避免直接以文本查看源码，不是强加密。源码版可在已有Python环境或PyCharm中运行 `main.py`。微信需已安装并打开目标小游戏。旧微信配置的迁移规则见“设置与升级”。
源码方式要求Windows、Python 3.10或以上，以及以下依赖：

```bash
python -m pip install -r requirements.txt
python main.py
```

使用PyCharm时，打开包含 `main.py` 的项目文件夹并选择对应解释器。Anaconda已安装依赖时无需重新安装。源码运行需要Tkinter；若解释器不包含它，可在对应Conda环境安装 `tk`。游戏完整竖屏画面比例约336∶598。

需要自行制作包含依赖的发行包时，可参考 [Windows便携版构建](docs/WINDOWS.md)。

## 设置点击位置

在“钓鱼选项”设置点击位置X/Y，坐标相对于框选游戏画面，范围0～1。将基准点放在**圆形钓鱼按钮下半部与“开心收下”按钮重叠的位置**，并让整个随机偏移圆圈位于按钮内。

默认基准点为画面中央，首次使用必须按实际按钮位置调整。开启预览核对十字线及圆圈，并确认该位置能下钩、拉钩、完成黄条操作及关闭结算页。

## 框选完整游戏画面

1. 在微信中打开小游戏，运行助手，在第1步选择对应微信小游戏窗口。
2. 点击“2. 框选完整游戏画面”，在3秒内切回游戏窗口。
3. 在截图里从游戏左上角拖到右下角，确认选区。

**只选完整的竖屏游戏区域。微信窗口顶部工具栏、标题栏和游戏外侧黑边不要选；游戏内部的底部黑色栏要保留。** 不要只框鱼、黄条或钓鱼按钮，也不要漏掉顶部、左右边缘或底部界面。

下图为历史框选素材，用于说明完整游戏边界；微信外框以当前窗口为准。示例处于结果页，其他阶段使用相同选区。程序内的“查看框选示例”也可打开此图。

![框选示例：保留完整游戏和底部游戏栏，排除外侧边框与工具栏](docs/images/crop-example.png)

窗口列表按微信进程归属筛选，游戏标题无需包含“微信”，例如“塔塔冒险队”也可列出。窗口列表没有其他应用回退入口；若未列出，请确认小游戏已在PC版微信中打开并刷新。

调整游戏窗口大小后，应停止监测并重新框选。仅移动窗口时程序会跟随其位置。游戏必须保持可见且无遮挡。

## 开始与暂停

1. 在“钓鱼选项”中设置是否不停钓、截图间隔以及次数／分钟上限。
2. 点击“3. 应用设置并开启监测”。此时只进行截图识别，尚未自动钓鱼。
3. 首次先保持“仅观察”，点击第4步并切回游戏；确认识别和点击位置后，停止监测、取消“仅观察”、重新应用设置，再启动钓鱼。也可切回游戏按默认 **F8** 开始。
4. 顶部出现“自动点击 · 运行中”后开始自动操作。

新配置默认勾选“仅观察”；勾选后只查看识别结果，不发送点击。重新打开时保留已保存的观察选择，每次打开软件都保持暂停。

点击助手、浏览器或其他窗口会使游戏失焦并暂停。返回游戏后需要重新启动。点击项目链接或打开框选示例也会暂停操作。关闭程序会停止后台循环并尝试释放本程序尚未抬起的鼠标键。

| 功能 | 默认快捷键 |
|---|---|
| 开始／暂停 | F8 |
| 紧急暂停、取消3秒启动 | F9 |
| 保存游戏截图 | F10 |

在“快捷键与延迟”页可改为F1～F12中的其他键，三个键不能重复。修改前停止监测，修改后重新点击第3步应用。界面显示当前生效键，避免与微信或其他软件的热键冲突。

## 不停钓与截图频率

默认勾选“不停钓”，次数和分钟两个上限都不生效，完成结算后继续下一条。取消勾选后恢复限制。每次重新启动钓鱼会重新计算次数和时长。

持续模式仍保留手动暂停、失焦和无响应保护，不会盲目点击未知弹窗或购买、补充鱼饵等按钮。

在“快捷键与延迟”页可设置“画面未确认等待”，默认60秒；“黄条阶段等待”默认120秒。两项范围均为0～3600秒，填0关闭对应自动超时。未确认画面期间只观察，不发送点击；F9及失焦暂停继续有效。

“每多少帧截图一次”接受1～60的整数，按**每秒60个基准帧**换算时间，不读取游戏内部帧号。

| 输入值 | 截图间隔 | 每秒截图目标 |
|---:|---:|---:|
| 6（默认） | 100毫秒 | 10次 |
| 12 | 200毫秒 | 5次 |
| 30 | 500毫秒 | 2次 |
| 60 | 1000毫秒 | 1次 |

追求识别响应速度可调小；电脑卡顿时可调大，降低截图和识别开销。数值增大也会减慢采样，更容易错过短暂的上钩提示，较小的值并不保证总钓鱼效率更高。黄条点击使用单独的期限，不需要等下一张截图；接近目标或进行校准时也不额外加密截图。界面显示实际截图次数。预览默认隐藏；隐藏时跳过标注绘图和界面图像转换。临近按键期限时会先处理按键再截图，实际截图频率可能略低于设置值。

## 结算与黄条判定

结果页连续确认后默认等待3秒，再点击。如果画面仍是纪录结算页或“开心收下”，约每1秒重试一次，每次间隔随机浮动±40毫秒，没有重试次数上限。每次操作都依据新截图；离开结算页后停止关闭动作，确认初始界面后再下钩。系统卡顿和截图处理可能延长实际间隔。

“开心收下”通过标题、绿色按钮局部和暗背景组合识别。纪录页通过重量图标、蓝色／紫色／金黄色／红橙渐变面板和暗背景组合识别，不依赖鱼的名称或“个人／团队纪录”标题。未知界面仍不按键。纪录页与收下页之间切换共用一次结算流程。

黄条阶段以固定比例速度维护连续运动相位：初始向右，到端点按时间反向，后续截图校正位置。多轮判定从上一轮的位置继续，不把每轮重置到起点。

鱼漂中心已经在黄色区域时立即按键；尚未进入时，预约下一次经过黄条中部的点击时刻，包含先到端点再折返的路线。目标很窄也不会因为固定安全边距而停止操作。同一趟经过只按一次；黄条变为下一轮后可再次按键，同一黄条未变时则允许在下一次经过时重试。

预览绿框表示黄色目标，红线表示鱼漂，紫线表示预测生效位置。时序原理和适用边界见 [算法说明](docs/ALGORITHM.md)。

## 比例速度与校准

“速度与校准”页默认显示参考速度 **60.6%条宽/秒**。比例单位是判定条可见外框的全宽；鱼漂中心的实际行程会扣除左右端帽及装饰。计算不依赖原始设备的像素大小。

不勾选校准时使用本机已保存速度；没有本机参数时用参考值。勾选“本次校准速度”后，使用正常截图中的同向位移区间，采样间隔小于0.25秒时先累计同向位移区间，再剔除零位移、跨端点、输入动效附近和明显离群值。双向样本稳定后保存结果并结束校准；不足时保留原值，不反复覆盖。校准不会额外增加截图次数，也不会写入原始轨迹。

结果保存在本机 `speed_profile.json`，升级时可复制到新目录；不要公开上传。需要恢复初值时点击“恢复参考速度”。截图仍先归一化到336×598；改变宽高比造成控件重新排版时，比例速度不能代替识别适配。

“游戏响应延迟基准”默认40毫秒，可根据设备调整。自动补偿只学习可测量的本机输入执行耗时，不能自动得知游戏内部完整响应延迟。低频预测假设两帧之间近似匀速，暂不通过停帧检测取消计划；游戏长停顿、变速或系统调度延迟仍可能造成误差。建议从准备下钩界面启动。

## 设置与升级

设置在点击第3步时保存；便携版保存在 `data/config.json`，源码版保存在项目根目录的 `config.json`，首次使用无需手工创建。`config.example.json` 仅用于展示默认配置，不包含任何个人框选。

| 常用配置 | 默认 | 含义 |
|---|---:|---|
| `dry_run` | true | 仅观察，不发送鼠标点击 |
| `click_point` | [0.5,0.5] | 鼠标点击基准位置（游戏画面比例坐标），预览显示黄色十字线 |
| `click_jitter_ratio` | 0.015 | 随机半径占画面短边的比例；界面显示1.5%，0关闭，最大5% |
| `click_hold_ms` | 30 | 单次点击按下到抬起的时长 |
| `continuous_fishing` | true | 勾选后忽略次数与分钟上限 |
| `capture_every_n_frames` | 6 | 每N个基准帧截图一次 |
| `input_latency_ms` | 40 | 游戏响应延迟基准，另加有界的本机执行补偿 |
| `timing_mode` | phase | 连续往返计时与低频位置校正 |
| `unknown_timeout_s` | 60 | 未确认画面的最长等待秒数，0不限 |
| `timing_timeout_s` | 120 | 黄条阶段最长等待秒数，0不限 |
| `speed_fraction_per_s` | 0.606 | 无本机校准文件时使用的比例速度；校准文件优先 |
| `calibrate_speed` | false | 当前监测请求校准；重开程序不会自动勾选 |
| `adaptive_latency` | true | 学习可测量的本机执行耗时，不等于自动测得游戏延迟 |
| `show_preview` | false | 是否显示识别预览 |
| `min_action_interval_s` | 0.9 | 拉钩及黄条操作的最小间隔 |
| `result_wait_s` | 3 | 结算首次等待秒数 |
| `result_retry_s` | 1 | 结算重试基准间隔 |
| `result_retry_jitter_ms` | 40 | 结算重试间隔浮动毫秒数 |
| `max_casts` | 20 | 未勾选不停钓时的下钩次数上限 |
| `max_session_minutes` | 15 | 未勾选不停钓时的分钟上限 |

配置v10仅保留微信设置。旧微信配置会移除环境选择、输入方式、截图后端和空格时长字段，保留观察选择、点击坐标、随机半径、快捷键和有效选区；旧版不高于0.24秒的动作间隔提升到0.9秒。不能确认属于微信的旧选区会清除，需要重新框选。旧模拟器环境或空格输入配置会明确报错，请先备份旧配置，再移除该配置文件并重新设置；程序不会自动改写原文件。便携版微信配置可随旧 `data/` 迁移；源码版配置位于根目录，迁入便携版时放入 `data/`。不要公开上传本机配置。

## 微信小游戏（实验性）

当前实时入口固定为PC版微信小游戏，使用mss截图和鼠标点击。点击位置在“钓鱼选项”调整；预览黄色十字线为基准点，圆圈为偏移范围，整个范围应落在下钩、拉钩及结算按钮的共同可点击区域内。

收敛前版本已在本机微信小游戏中验证截图、阶段识别和限次钓鱼闭环；随机偏移开启后的2次下钩均确认结算，8次点击落点各不相同。一次观察校准取得20个有效内点，保存速度约60.54%条宽/秒，并完成1次结算。当前微信专用版通过200项离线自检和14项开发PoC回归；完整GUI流程、2/5/8分钟分级稳定性及不同游戏窗口尺寸仍待验收。其他DPI、多屏、设备和微信版本环境暂不验证。具体记录见开发仓库的 `docs/HANDOVER.md`，该文档和PoC脚本不随包分发。

“随机偏移半径”默认填1.5，表示画面短边的1.5%；例如短边686像素时约为10像素。每次点击在该圆形范围内选择像素，保持在游戏框选内，并避免连续落在同一像素；填0恢复固定点。此功能不能保证避免平台检测或账号处罚。

使用注意事项：

- 首次使用或游戏时序变化后，可勾选“本次校准速度”重新校准。
- 点击是否能被小游戏识别为触摸、截图是否正常（WebGL硬件加速可能导致黑屏），与微信版本和显卡环境有关。仓库内 `tools/poc/` 提供窗口枚举、截图、启动和点击诊断脚本；截图脚本会保存图片，启动脚本默认会启动微信，点击脚本会真实点击。脚本支持模块及直接路径启动，截图和点击默认倒计时5秒后确认前台微信目标，每次操作检查焦点与窗口位置，F9/Esc可取消；具体命令见开发仓库的交接文档。
- 微信侧存在反自动化风控，自动点击可能导致小程序功能受限或账号被处罚。新配置默认勾选“仅观察”，请自行确认平台规则后再关闭。
- 微信选区复用依据微信标记、客户区尺寸及有效框选结构，不要求窗口标题一致；复用前请确认所选窗口确为目标游戏，窗口尺寸变化后重新框选。

## 本地文件与排查

正常钓鱼不自动保存运行日志、轨迹、截图或诊断ZIP，暂停和F9也不会打包数据。设置和明确完成的速度校准保存在本机。按F10才保存游戏截图；“录制”页的手动录制会暂停自动点击，保存15秒视频及对应时间戳。

| 现象 | 检查方法 |
|---|---|
| 第3步后没有动作 | 还需第4步或开始快捷键；查看顶部是否运行、是否勾选仅观察 |
| 开心收下未退出 | 核对点击基准及随机范围是否位于按钮内，且画面被识别为结果页 |
| 一直显示未知画面 | 核对完整框选、游戏外黑边、遮挡和弹窗 |
| 运行中暂停 | 查看顶部原因；游戏失焦后需要重新启动 |
| 点击不生效 | 检查点击位置、窗口遮挡及助手与微信的权限级别 |
| 判定持续偏早或偏晚 | 核对比例速度与延迟基准；可显式校准速度，不需每次启停校准 |

离线检查不发送系统输入：

```bash
python selfcheck.py
python replay.py
```

`replay.py` 默认检查文档中的框选示例，也支持 `--input` 指定自己的图像或录像，以及 `--crop X Y W H` 指定游戏范围。它只输出拟议动作，不证明真实游戏执行或命中。

公开分享材料前移除昵称、聊天内容、账号信息和本机路径。程序没有自动上传功能；更多说明见 [本地数据与公开发布](docs/PRIVACY.md)。

## 上传与贡献

本发布包解压后的 `README.md`、`main.py`、`fisher/`、`assets/` 等应放在仓库根目录，不再额外套一层工程文件夹。

